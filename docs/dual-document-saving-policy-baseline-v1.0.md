# THERMOPAC Dual Document Saving Policy — Baseline v1.0

**Status**: Approved for implementation  
**Supersedes**: `docs/dual-storage-policy-proposal-v1.0.md` (proposal stage — this document is the definitive implementation baseline)  
**Date**: 2026-06-17  

---

## 1. Final Policy Statement

Every file created, uploaded, or system-generated by the THERMOPAC ERP must be saved in exactly two places:

| Layer | Storage | Role |
|---|---|---|
| **Primary** | Google Cloud Storage (GCS) | Source of truth for all ERP operations, reads, downloads, and audit |
| **Mirror** | Windows File Server via Local Document Agent | Local repository for desktop/Windows Explorer access |

**GCS is always written first. The Windows mirror is dispatched asynchronously via `document_agent_jobs` immediately after GCS succeeds.**

This policy is non-negotiable and applies uniformly to:
- **User-uploaded documents** — files submitted via ERP upload forms
- **System-generated documents** — PDFs, reports, and any file produced programmatically (Offers, Final Offers, DDS PDFs, appraisal PDFs, payroll reports, etc.)

### Governing principles

| # | Principle |
|---|---|
| P1 | GCS Governance Rule is the master source for path generation. No exceptions. |
| P2 | Every file write must call `resolveGcsPath(documentType, tokens)` from `server/utils/gcs-path-resolver.ts`. |
| P3 | No hardcoded GCS paths are permitted in any route or service. |
| P4 | No local filesystem fallback is permitted. If GCS is unavailable, the operation must fail. |
| P5 | GCS upload failure → operation fails entirely. No DB record. No agent job. |
| P6 | GCS upload success → DB record created → `SAVE_FILE` agent job enqueued. This sequence is inviolable. |
| P7 | Downloads always use GCS signed URLs. The Windows copy is never used for ERP reads. |
| P8 | Mirror failure does not invalidate the document. GCS is authoritative. No GCS rollback on mirror failure. |
| P9 | No document is deleted or archived unless a separate destruction policy is approved. |
| P10 | Document Path Templates are downstream mirrors of GCS Governance Rules only. No active template may exist without `gcs_rule_id`. |
| P11 | All source table rows and `document_agent_jobs` rows are permanent. `is_active` may be flipped; rows are never deleted. |
| P12 | No signed URL is ever stored in the database. Generated fresh at `jobs/claim` time only. |

## 2. Required Implementation Checklist — Every Upload/Generation Route

Every route that writes a file to storage must satisfy all items before it is considered compliant.

### 2A. Path Resolution

- [ ] Calls `resolveGcsPath(documentType, tokens)` from `server/utils/gcs-path-resolver.ts`
- [ ] No hardcoded GCS path strings anywhere in the route or its called services
- [ ] If `resolveGcsPath` returns `null` / throws → route returns HTTP 503 `GCS_GOVERNANCE_ERROR`
- [ ] All `{Token}` placeholders fully resolved — no unresolved tokens pass to GCS

### 2B. GCS Upload

- [ ] File buffer uploaded to GCS using the resolved path from `resolveGcsPath`
- [ ] GCS failure → return error to caller; stop; no DB record created; no agent job created
- [ ] SHA-256 of buffer computed **after** upload confirmation (or before, stored for verification)

### 2C. Database Record

- [ ] DB record created **only after** GCS upload confirms success
- [ ] DB record stores: `gcs_path` (the resolved GCS object key), `sha256` / `checksum_sha256`, `mirror_status = 'pending'`, `mirror_job_id = null` (filled after job creation)
- [ ] No orphan DB records on GCS failure

### 2D. Mirror Job

- [ ] `document_agent_jobs` row inserted after DB record created
- [ ] `job_type = 'SAVE_FILE'`
- [ ] `relative_path` set to the GCS object key (identical to Windows agent relative path — no translation)
- [ ] `expected_sha256` set to the computed SHA-256 of the file
- [ ] `source_module` set to the source table name
- [ ] `source_record_id` set to the newly created DB record ID
- [ ] `created_by` set to the authenticated user ID
- [ ] If job insertion fails → DB record `mirror_status = 'failed'`; do NOT roll back GCS or DB record

### 2E. Source Table Mirror Status

- [ ] Source table row has `mirror_status` column (`pending` / `mirrored` / `failed`)
- [ ] Source table row has `mirror_job_id` column (FK/reference to `document_agent_jobs.id`)
- [ ] After agent reports `complete` → `mirror_status = 'mirrored'`, `mirror_job_id` updated
- [ ] After agent reports `failed` → `mirror_status = 'failed'`

### 2F. Download

- [ ] All download routes use GCS signed URL (generated fresh per request)
- [ ] No download route reads from Windows path

## 3. Standard File Save Sequence

### 3A. User-Uploaded Document

```
[Browser] → POST /api/.../upload
    │
    ├─ 1. Authenticate + authorise
    ├─ 2. Validate file (MIME type, size)
    ├─ 3. resolveGcsPath(documentType, tokens)
    │       └─ No active rule → HTTP 503 GCS_GOVERNANCE_ERROR; STOP
    │
    ├─ 4. Compute SHA-256 of file buffer
    │
    ├─ 5. Upload buffer → GCS at resolved path
    │       └─ GCS failure → HTTP 500/502; no DB; no job; STOP
    │
    ├─ 6. INSERT source table row
    │       (gcs_path, sha256, mirror_status='pending', mirror_job_id=null)
    │
    ├─ 7. INSERT document_agent_jobs
    │       (SAVE_FILE, relative_path, expected_sha256, source_module, source_record_id, ...)
    │       └─ Job insert fails → UPDATE source row mirror_status='failed'; log error
    │
    ├─ 8. UPDATE source row mirror_job_id = new job id
    │
    └─ 9. Return HTTP 201 with source record to browser
```

### 3B. System-Generated Document

```
[ERP trigger: user action / scheduled job]
    │
    ├─ 1. Generate document in memory (PDF buffer, JSON, etc.)
    │
    ├─ 2. resolveGcsPath(documentType, tokens)
    │       └─ No active rule → fail generation; return error; STOP
    │
    ├─ 3. Compute SHA-256 of generated buffer
    │
    ├─ 4. Upload buffer → GCS at resolved path
    │       └─ GCS failure → fail generation; no DB; no job; return error; STOP
    │
    ├─ 5. INSERT source table row
    │       (gcs_path, sha256, mirror_status='pending', mirror_job_id=null)
    │
    ├─ 6. INSERT document_agent_jobs
    │       (SAVE_FILE, relative_path, expected_sha256, source_module, source_record_id, ...)
    │       └─ Job insert fails → UPDATE source row mirror_status='failed'; log error
    │
    ├─ 7. UPDATE source row mirror_job_id = new job id
    │
    └─ 8. Return success to caller (with generated document reference)
```

### 3C. Agent Claim + Write Flow

```
[Windows Agent] → POST /api/local-agent/jobs/claim
    │
    ├─ ERP selects next pending SAVE_FILE job
    ├─ ERP generates fresh GCS signed URL for relative_path  ← never stored in DB
    ├─ ERP marks job status = 'claimed', claimed_at = NOW()
    ├─ ERP returns: { jobId, signedUrl, localRelativePath, expectedSha256 }
    │
    ├─ Agent downloads file from signedUrl
    ├─ Agent creates folder structure if missing
    ├─ Agent writes file to: allowedRootPath + localRelativePath
    ├─ Agent computes SHA-256 of written file
    │
    └─ Agent → POST /api/local-agent/jobs/result
            ├─ success (SHA256 match)
            │       → job: status='completed', completed_at=NOW(), actual_sha256=computed
            │       → source row: mirror_status='mirrored', mirror_job_id=jobId
            └─ failure
                    → job: status='failed', failed_reason=message
                    → source row: mirror_status='failed'
```

## 4. Standard DB Fields Required on Every Source Table

Every source table that stores a governed document must include the following columns. Add via migration if not present.

| Column | Type | Description |
|---|---|---|
| `gcs_path` | `TEXT NOT NULL` | GCS object key (relative path). No signed URL, no bucket prefix. |
| `sha256` or `checksum_sha256` | `VARCHAR(64)` | SHA-256 hex digest of the file at upload/generation time. |
| `mirror_status` | `VARCHAR(20) DEFAULT 'pending'` | `pending` / `mirrored` / `failed`. |
| `mirror_job_id` | `INTEGER` | Reference to `document_agent_jobs.id` of the active SAVE_FILE job. |
| `is_active` | `BOOLEAN DEFAULT true` | Whether this revision is the current active one. Never deleted. |
| `created_by` | `INTEGER` | User ID of the uploader or generation trigger. |
| `created_at` | `TIMESTAMPTZ DEFAULT NOW()` | Immutable creation timestamp. |

**Notes:**
- `gcs_path` must store only the relative object key (e.g. `TPEL/COMPANY/TPEL/GST_CERTIFICATE/rev-01/001-gst-certificate.pdf`). Never the full `gs://` URI.
- `mirror_job_id` is nullable until the job is created; set to `null` if job creation fails.
- Rows are never deleted; only `is_active` is toggled between revisions.

## 5. Standard `document_agent_jobs` Payload

### Table columns used by every SAVE_FILE job

| Column | Value |
|---|---|
| `job_type` | `'SAVE_FILE'` |
| `status` | `'pending'` (initial) |
| `relative_path` | GCS object key — identical string used as Windows agent local relative path |
| `file_name` | Filename component of the path (last segment after final `/`) |
| `expected_sha256` | SHA-256 hex of the uploaded/generated buffer |
| `source_module` | Source table name (e.g. `vendor_compliance_docs`, `company_documents`) |
| `source_record_id` | PK of the newly inserted source table row |
| `source_ref` | Human-readable reference (e.g. BP code, project code, document number) |
| `created_by` | Authenticated user ID |

### Columns populated by agent on completion

| Column | Value |
|---|---|
| `agent_code` | Agent's registered code |
| `claimed_at` | Timestamp when agent claimed |
| `completed_at` | Timestamp when agent reported result |
| `actual_sha256` | SHA-256 agent computed after writing |
| `result_local_path` | Full Windows path where file was written (for audit) |
| `failed_reason` | Error detail on failure |

### What is never stored

| Field | Reason |
|---|---|
| Signed URL | Expires; generated fresh at `jobs/claim` time; returned in response only |
| Full GCS URI (`gs://...`) | Not needed; agent uses relative path only |
| Windows `allowedRootPath` | Owned by agent `config.json`; not in ERP database |

### Agent immutability guard (enforced by agent, verified by ERP)

| Condition | Agent Action |
|---|---|
| Target file does not exist | Write file; report success |
| Target file exists, SHA-256 matches | Report `FILE_ALREADY_EXISTS_IDENTICAL`; no write |
| Target file exists, SHA-256 differs | Report `FILE_ALREADY_EXISTS_CONFLICT`; no write; governance violation |

## 6. Exception Handling Rules

| Step | Event | Required Action |
|---|---|---|
| Path resolution | `resolveGcsPath` finds no active rule for `documentType` | Return HTTP 503 `GCS_GOVERNANCE_ERROR`; stop; no file written; no DB record |
| Path resolution | Any `{Token}` unresolved after substitution | Return HTTP 400; stop; no file written; no DB record |
| File validation | MIME type not in `allowedMimeTypes` for rule | Return HTTP 415; stop |
| File validation | File size exceeds `maxFileSizeMb` for rule | Return HTTP 413; stop |
| GCS upload — user upload | GCS write fails | Return HTTP 502 to browser; no DB record; no agent job; log error with `[GCS-UPLOAD-FAIL]` |
| GCS upload — system generated | GCS write fails | Return error to caller; no DB record; no agent job; log error with `[GCS-GENERATE-FAIL]` |
| DB record insert | Fails after GCS success | Critical: GCS write is NOT rolled back (GCS is immutable from ERP side). Return HTTP 500; log with `[DB-INSERT-FAIL-POST-GCS]` — requires manual investigation |
| Agent job insert | Fails after DB record created | Do NOT roll back GCS or DB record. Set `mirror_status = 'failed'` on source row. Log `[MIRROR-JOB-FAIL]`. Document remains valid; mirror retryable. |
| Agent — file download fails | Network error from signed URL | Agent reports `failed`; job marked `failed`; source row `mirror_status = 'failed'`; retryable |
| Agent — SHA-256 mismatch | Written file hash ≠ `expected_sha256` | Agent reports `failed` with detail; job marked `failed`; source row `mirror_status = 'failed'`; retryable |
| Agent — path collision (identical) | `FILE_ALREADY_EXISTS_IDENTICAL` | Job marked `failed` with reason; source row `mirror_status = 'failed'`; no overwrite |
| Agent — path collision (conflict) | `FILE_ALREADY_EXISTS_CONFLICT` | Job marked `failed` with reason; governance violation alert; escalate to Superuser |
| Agent offline | No agent heartbeat | Jobs remain `pending` indefinitely; no expiry; no action required until agent reconnects |
| Retry | Uploader or Superuser retries | Insert new `document_agent_jobs` row; do NOT mutate original failed row |

## 7. Audit and Verification Queries

### Q1 — Count total templates and any unlinked

```sql
SELECT
  COUNT(*)                                          AS total_templates,
  COUNT(*) FILTER (WHERE gcs_rule_id IS NULL)       AS unlinked,
  COUNT(*) FILTER (WHERE gcs_rule_id IS NOT NULL)   AS linked
FROM document_path_templates;
-- Expected: unlinked = 0 always
```

### Q2 — Identify unlinked templates (must return zero rows)

```sql
SELECT id, template_code, document_type, document_category, relative_path_template, created_at
FROM document_path_templates
WHERE gcs_rule_id IS NULL
ORDER BY id;
```

### Q3 — Mirror job status summary (all modules)

```sql
SELECT
  source_module,
  status,
  COUNT(*) AS job_count
FROM document_agent_jobs
WHERE job_type = 'SAVE_FILE'
GROUP BY source_module, status
ORDER BY source_module, status;
```

### Q4 — Documents with mirror_status = 'failed' (company_documents)

```sql
SELECT id, company_id, doc_type, gcs_path, mirror_status, mirror_job_id, created_at
FROM company_documents
WHERE mirror_status = 'failed'
ORDER BY created_at DESC;
```

### Q5 — Documents with mirror_status = 'failed' (vendor compliance)

```sql
SELECT id, vendor_id, doc_type, gcs_path, mirror_status, mirror_job_id, created_at
FROM vendor_compliance_docs
WHERE mirror_status = 'failed'
ORDER BY created_at DESC;
```

### Q6 — Pending SAVE_FILE jobs older than 1 hour (agent may be offline)

```sql
SELECT id, source_module, source_record_id, relative_path, status, created_at,
       EXTRACT(EPOCH FROM (NOW() - created_at)) / 3600 AS hours_pending
FROM document_agent_jobs
WHERE job_type = 'SAVE_FILE'
  AND status = 'pending'
  AND created_at < NOW() - INTERVAL '1 hour'
ORDER BY created_at;
```

### Q7 — GCS governance rules with no linked document path template

```sql
SELECT r.id, r.module_key, r.document_type, r.display_name, r.active
FROM gcs_governance_rules r
LEFT JOIN document_path_templates t ON t.gcs_rule_id = r.id
WHERE t.id IS NULL
  AND r.active = true
ORDER BY r.module_key, r.document_type;
-- Expected: zero rows (every active rule should have a linked template)
```

### Q8 — Active rules with no SAVE_FILE job activity (never mirrored)

```sql
SELECT r.module_key, r.document_type, COUNT(j.id) AS save_file_jobs
FROM gcs_governance_rules r
LEFT JOIN document_agent_jobs j
  ON j.source_module = r.document_type
  AND j.job_type = 'SAVE_FILE'
WHERE r.active = true
GROUP BY r.module_key, r.document_type
HAVING COUNT(j.id) = 0
ORDER BY r.module_key, r.document_type;
-- Identifies active governed document types with zero mirror history
```

### Q9 — SHA-256 mismatch incidents (governance violations)

```sql
SELECT id, source_module, source_record_id, relative_path,
       expected_sha256, actual_sha256, failed_reason, completed_at
FROM document_agent_jobs
WHERE job_type = 'SAVE_FILE'
  AND failed_reason LIKE '%FILE_ALREADY_EXISTS_CONFLICT%'
  OR  failed_reason LIKE '%SHA-256%'
ORDER BY completed_at DESC;
```

### Q10 — Full mirror health summary across all governed source tables

```sql
-- Run individually per table:
SELECT 'company_documents' AS module, mirror_status, COUNT(*) FROM company_documents GROUP BY mirror_status
UNION ALL
SELECT 'vendor_compliance_docs',    mirror_status, COUNT(*) FROM vendor_compliance_docs    GROUP BY mirror_status
ORDER BY module, mirror_status;
-- Add more tables as each module is brought into compliance
```

## 10. Approved Decisions (inherited from v1.0 proposal, confirmed)

| # | Decision |
|---|---|
| D1 | GCS is the primary source of truth for all ERP read/download operations |
| D2 | Windows Server is mirror only — ERP never reads from it |
| D3 | No signed URL stored in DB — generated fresh at `jobs/claim` |
| D4 | `document_agent_jobs` extends the existing table — no new table |
| D5 | Mirror confirmation requires all 4 steps: download → write → SHA256 verify → report |
| D6 | Agent offline → jobs stay `pending` indefinitely; no expiry |
| D7 | Retry: original uploader or Superuser; new job row; original failed row preserved |
| D8 | Policy scope: all modules with an active GCS governance rule |
| D9 | GCS path = Windows agent `local_relative_path` — identical strings, no translation |
| D10 | System-generated doc — GCS failure → no DB record created; no orphan state |
| D11 | No document overwrite in GCS or Windows — every replacement is a new revision at a new path |
| D12 | Agent must refuse to overwrite: `FILE_ALREADY_EXISTS_IDENTICAL` or `FILE_ALREADY_EXISTS_CONFLICT` |
| D13 | Latest revision determined by DB metadata only (`is_active`, `revision_number`) — never by file inspection |
| D14 | Source table rows and agent job rows are permanent — never deleted |
| D15 | No active `document_path_templates` row without `gcs_rule_id` |
