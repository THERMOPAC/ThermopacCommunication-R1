# HAZOP Phase 5A Hardening — v1.1 Baseline
**Date:** 2026-05-25  
**Status:** IN PROGRESS — pre-approval corrections  
**Supersedes:** Phase 5A initial delivery (checkpoint 6e786ee)

---

## 1. Purpose

The initial Phase 5A LOPA engine was rejected at UAT because the arithmetic
engine over-credited IPLs, producing unrealistically optimistic MEF values
(all six study-1 scenarios showed MEF ≈ 1e-16 per year with 10 credited IPLs
per scenario). This document records the seven mandatory corrections required
before Phase 5A can be approved.

---

## 2. Identified Defects

| ID | Defect | Impact |
|----|--------|--------|
| 5A-D002 | `is_independent` flag NOT checked before crediting IPL in product | All non-independent IPLs over-credited |
| 5A-D003 | `common_cause_group` derating NOT applied | Multiple IPLs sharing CCF group all credited individually |
| 5A-D004 | No warning for excessive credited IPL count (>3) | Silent over-crediting |
| 5A-D005 | `creditable` boolean missing from `hazop_scenario_ipl_stack` | No per-item traceability of who is credited |
| 5A-D006 | Arithmetic audit fields missing from `hazop_lopa_records` | No auditability of engine inputs/outputs |
| 5A-D007 | No warning when MEF < 1e-12/year | Unrealistically optimistic results pass silently |
| 5A-D008 | `pfd_source` and `ccf_group` not stored on stack item | Traceability gap |

## 3. Corrections Applied (v1.1)

### 3.1 Schema Additions (additive DDL only)

**`hazop_scenario_ipl_stack` (2 new columns):**
- `creditable boolean` — set by the arithmetic engine after recalculate; `true` means this item's PFD was multiplied into the product
- `ccf_group text` — denormalized from the source response group at build time for traceability

**`hazop_lopa_records` (5 new columns):**
- `credited_ipl_count integer` — how many IPLs contributed to the PFD product
- `excluded_ipl_count integer` — how many IPLs were excluded (not independent or no PFD)
- `ccf_derated_count integer` — how many IPLs were excluded by CCF derating logic
- `arithmetic_version text` — engine version tag; v1.1 for all post-hardening calculations
- `warnings text[]` — array of advisory/warning strings generated by the engine

### 3.2 computeLopa() Engine — Version 1.1

Replaces the v1.0 function. Key changes:

**Eligibility gate (was missing):**
```
creditable_candidate = credit_applied = true
                       AND is_independent = true
                       AND pfd_value IS NOT NULL
                       AND pfd_value > 0
```

**CCF derating:**
- For each unique `ccf_group` value (non-null, non-empty) among creditable candidates,
  sort by PFD ascending and credit only the first (lowest PFD = most conservative).
- Remaining members of the same CCF group are counted in `ccf_derated_count`.
- Items with no CCF group are all credited individually.

**PFD product:**
```
PFD_product = ∏(PFD_i)  for all credited items
            = 1.0         if no credited items (no protection)
```

**Arithmetic (unchanged from v1.0):**
```
MEF          = IEF × PFD_product
risk_gap     = MEF / RTTF
outcome      = tolerable           if risk_gap ≤ 1.0
             | gap_exists          if RTTF/MEF > 0.01
             | requires_sif        if RTTF/MEF ∈ (0.001, 0.01]
             | requires_sif_upgrade if RTTF/MEF ≤ 0.001
required_SIL = ⌈−log₁₀(RTTF/MEF)⌉ clamped to [1,4]
```

**Warnings (new in v1.1):**
| Condition | Warning Text |
|-----------|-------------|
| credited_count > 3 | "Excessive IPL credit: {N} IPLs credited. Verify independence and CCF assumptions per IEC 61511." |
| MEF < 1e-12 | "Achieved MEF ({value} per year) is unrealistically optimistic. Review IPL independence and CCF assumptions." |

**Per-item `creditable` flag:**  
Set to `true` only for items that contributed to the PFD product.  
Set to `false` for items that were excluded (not independent, no PFD, or CCF-derated).

**`arithmetic_version` tag:** `'1.1'`

### 3.3 Build Route Hardening

The auto-build route (`POST /api/hazop/studies/:studyId/ipl-stack/:scenarioId/build`)
now fetches and stores `common_cause_group` from the source response group into
`hazop_scenario_ipl_stack.ccf_group` for traceability.

### 3.4 UI Additions

**LOPA List page (`hazop-lopa.tsx`):**
- Warning badge (orange triangle count) when `warnings` array is non-empty
- Audit strip: credited / excluded / CCF-derated counts
- `arithmetic_version` displayed as chip

**LOPA Detail page (`hazop-lopa-detail.tsx`):**
- `IplRow` now shows dual-status: `credit_applied` (user intent) vs `creditable` (engine decision)
- CCF-derated items shown with amber "CCF Excluded" badge
- Not-independent items shown with red "Not Independent" badge
- Warnings panel at top of results section
- Audit fields panel (credited, excluded, CCF-derated, engine version)

## 5. MEF Realism Reference

IEC 61511 guidance for creditable IPL count:

| Credited IPLs | Typical MEF reduction | Advisory |
|---|---|---|
| 0 | None (MEF = IEF) | Baseline |
| 1 | 10× – 1000× | Normal |
| 2 | 100× – 1,000,000× | Acceptable |
| 3 | Up to 1e9× | Borderline; review independence |
| >3 | >1e9× | Requires written justification |
| Any producing MEF < 1e-12 | >1e10× reduction | Unrealistically optimistic |
