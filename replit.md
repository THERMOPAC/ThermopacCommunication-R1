# Overview
This project is a comprehensive Quality Management System (QMS) for THERMOPAC, designed to streamline operations, enhance efficiency, and provide enterprise-grade insights. It supports core business modules including project management, production, quality control, inspections, welding procedures, materials, finance, HR, and document management. The system aims to drive data-driven decisions, offer advanced sales and marketing features with AI-powered lead generation, integrate with Google Ads, provide a global re-refining opportunity radar, and incorporate a multi-agent intelligence layer for proactive business management.

# User Preferences
Preferred communication style: Simple, everyday language.

# System Architecture
## Core Architectural Decisions
The system is a full-stack web application with organized, hierarchical data structures, ensuring consistent UI/UX through standardized components, robust data integrity, and real-time synchronization. It features role-based access control, comprehensive validation, and dialog-based editing with form pre-population. Google Cloud Storage (GCS) is the single source of truth for file metadata, with the database storing only GCS keys. Security is managed via signed URLs, and client-side caching optimizes performance. UI/UX emphasizes consistent color schemes, card-based layouts, unified dropdowns, and branded professional report generation.

## Technical Implementations
- **Backend**: Express.js with TypeScript, PostgreSQL (Drizzle ORM), session-based authentication, Google Cloud Storage, and a RESTful API.
- **Frontend**: React with TypeScript, Wouter for routing, TanStack Query for state management, Radix UI components with Tailwind CSS, React Hook Form with Zod validation, and Vite for builds. Lazy loading is implemented for module files.
- **Error Handling**: Centralized, structured error handling on both backend (error classes, global Express handler) and frontend (ApiError class). Errors follow a standard JSON format without exposing raw SQL/stack traces.
- **Data Storage**: PostgreSQL on Neon, a dedicated GCS bucket for files, and database-backed sessions.
- **Key Modules & Features**:
    - **Project & Quality Management**: Tracks projects, items, work orders, inspection orders, material identification, welder management, and welding procedures.
    - **Finance & HR Management**: Handles invoicing, payments, allocations, BRC tracking, GL Mapping, Statutory Compliance, two-phase TDS reconciliation, user management, attendance tracking with regularization, DWAR, and an enhanced payroll engine supporting dual tax regimes, tax declarations, and investment proof verification. Includes loan and advance management.
    - **Document Management**: Integrates with GCS for hierarchical storage, metadata tracking, templates, and access control. Includes Drawing Registry for version control, CAD management, and review workflows; and EPC Document Attachment & Retrieval with GCS-backed storage, SHA-256 duplicate detection, contextual download, revision-grouped listing, and audit history. All EPC document paths now use the TPEL hierarchy: `TPEL/{CC}/{CO}/{Cust}/{FY}/{ProjectCode}/{DocType}/{DocNumber}/{RevSlot}/{Seq}-{Label}.{ext}`. Quotation PDFs use a two-stage TPEL hierarchy: pre-conversion at `TPEL/{CC}/{CO}/{Cust}/{FY}/Quotations/{Offer}/rev-{NN}/{seq}-{label}.pdf`, post-conversion controlled copy at `TPEL/.../{ProjectCode}/QTN/{Offer}/rev-na/{seq}-{label}.pdf` with dual checksum verification. Customers table stores `continent_code` and `country_code` (ISO 2-letter) for GCS path construction. Full EPC→TPEL GCS migration completed: 273 objects (267 INS + 6 DWG) migrated with SHA-256 checksum verification. Old EPC/ objects retained in GCS for cleanup after 30+ days.
    - **Sales & Marketing**: AI-powered lead generation, product database, offer/quotation module, Google Ads integration, and Commercial Change Order (CCO) control linking Sales and EPC with sequential ordering, approval gates, ECR linkage, and computed financial traceability. Commercial Chain Model tracks offer lineage via `commercial_chain_id` (UUID), `parent_offer_id`, and `root_offer_id` on the offers table, with DB triggers enforcing root self-reference, chain integrity validation, and chain field immutability after confirmation/CCO linkage. Chain timeline visualized on the Commercial tab.
    - **EPC Document Control**: DocType-based document control system replacing folder-based file storage. 21 EPC DocTypes (17 slot types + 4 sequential types). Slot documents: one per project per folder with revision control (3D, BEDD, STD, PID, MHB, HAZ, QAP, TIE, GA, FDN, ELC, PRG, CEF, DSA, INR, DCA, OMM). Sequential documents: multiple per project (DWG, ECR, ECN, IAT). All stored at `TPEL/{CC}/{CO}/{Cust}/{FY}/{OpCode}/{DocType}/rev-{XX}/{Seq}-{Label}.{ext}`. DB tables: `epc_doc_types` (registry with allowed_extensions, max_file_size_mb, upload_mode), `epc_documents` (unified document records with revision tracking, checksum_sha256, supersession). Folder names are UI-only — never in GCS paths. DWG remains separate multi-document drawing register using existing numbering system. Duplicate handling: block same-folder same-project, warn cross-folder, allow cross-project. Phase 2 backend complete (`server/document-control-routes.ts`): 6 API endpoints covering folder listing, document history, upload with revision/supersession, download via signed URLs, and project summary. Transaction-safe uploads with GCS cleanup on failure. Extension + MIME + file size validation. Zero-Trust Backend Audit passed 8/8. Phase 3 frontend complete (`client/src/components/document-control.tsx`): Replaced legacy "Files" tab with "Document Control" tab on `/projects/{id}`. 17 folder cards with color-coded status, folder detail with revision history grouped by revision, upload dialog with validation warnings, download via signed URLs, progress tracking (X/17 populated). Zero-Trust UI Audit passed 8/8. Legacy File Storage lockdown: all write endpoints (`POST /api/storage/directories`, `POST /api/storage/upload-url`, `POST /api/storage/upload`, `DELETE /api/storage/files`) return 403 with `LEGACY_STORAGE_LOCKED` code. Read/download endpoints remain active for existing files. Legacy data (80 `project_documents`, 59 `gcs_directories`) retained as read-only reference. Migration deferred to post-stabilisation.
    - **EPC Control Layers**: Enforces governance for design drawings (revision control), Bill of Materials (BOM lifecycle management), and project-scoped operational codes/document numbers for 16 EPC document types.
    - **Multi-Agent Intelligence & Automation**: Features 11 agents with conflict control, event bus, finding management, and audit logging. Includes dashboards for worker agents and live EPC risks.
    - **Employee Appraisal Module**: Hierarchical workflow, KPI/competency scoring, increment policies, L3 decision support, and PDF report generation.
    - **Alert Management System**: Full alert system with priority levels and a 3-state workflow.
    - **Security & Access Control**: API Security (SQL injection, XSS protection), TOTP-based Two-Factor Authentication (2FA), EPC Permission Control Dashboard (role-based, department-based, and user-override access with audit logging), and EPC Record-Level Ownership Filtering.
    - **EPC Control Integrity**: Manages project status cascades (cancellation + restoration), BOM reconciliation, DWG linking enforcement, and automated inspection triggers. Includes stage-gate enforcement for planning records before PO/WO creation. Project cancellation cascade stores affected record IDs for auditing. Project reopen (Superuser only) supports `canceled → on_hold` (audit only, no restore) and `canceled → planning` (full restoration of safe records). Restoration is idempotent; POs/WOs/dispatch records/invoices are never auto-restored and generate a review task.
    - **EPC Control Tower**: A program-level monitoring dashboard providing project summaries, pipeline analysis, bottleneck identification, ownership gap analysis, blocking analysis, and risk indicators, with the ability to generate actionable tasks.
    - **EPC Cutover Readiness Dashboard**: Monitors the migration progress and adoption of EPC features, identifying pending uploads, legacy system usage, and BOM readiness.
